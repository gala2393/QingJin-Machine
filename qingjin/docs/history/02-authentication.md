# 数据模型、登录鉴权与角色

## 模型与迁移

qingjin/server/prisma/schema.prisma 定义用户、刷新令牌、分类、参数模板、机型、参数、媒体、图片关联、站点设置、发布版本、审计日志、访问事件和每日统计。

现有迁移目录依次为 20261014130034_init、20261014130311_model_key 和 20261014143855_track_channel。迁移名称只用于标识数据库变更，不据此推定其他功能完成时间。

机型状态为 DRAFT、PUBLISHED、HIDDEN；发布状态为 PENDING、BUILDING、SUCCESS、FAILED。数据库中的上架状态与已经构建上线的页面需要分别理解。

## 登录与刷新流程

1. 查询账号，使用 bcrypt 比较密码；账号不存在时也执行散列比较，降低时序差异。
2. 成功后更新最近登录时间、写审计日志，签发访问令牌和随机刷新令牌。
3. 数据库保存刷新令牌 SHA-256 摘要、会话链及有效期，不保存其原文。
4. 刷新时撤销旧令牌，并使用条件更新避免同一令牌被并发使用成功两次。
5. 重用已撤销的刷新令牌会撤销整条刷新会话链并记录异常。

默认部署访问令牌为 15 分钟，刷新令牌为 7 天，实际值取决于配置。

## 权限和账号保护

| 角色 | 主要职责 |
| --- | --- |
| SUPER_ADMIN | 内容管理，用户角色、操作日志及备份等受限管理 |
| EDITOR | 获准的产品编辑、站点维护、发布及导入操作 |
| VIEWER | 查看允许访问的内容，写入权限仍以服务端守卫为准 |

全局守卫默认要求 Bearer 令牌，公开入口需显式标记；受保护请求重新读取账号启用状态和当前角色。后台路由限制不能代替服务端授权。

用户管理禁止删除或停用自己、修改自己的角色，并检查其他启用超级管理员。角色变更和停用会撤销刷新会话；自行改密可保留当前会话链。刷新会话撤销不等于立即撤销所有尚未到期的访问令牌。
