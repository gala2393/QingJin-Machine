# 发布、预览与历史回滚

## 三种独立记录

Git 记录源码变化，数据库保存正在编辑的业务内容，发布版本保存用于构建展示站的快照。代码推送、保存内容和网站上线是不同动作。

## 发布流程

1. 从数据库生成快照，与当前成功版本比较待发布差异。
2. 检查任务状态，创建发布记录，保存快照；没有已上架机型时拒绝发布。
3. 构建任务进入队列，状态转为 BUILDING。
4. 在临时工作目录生成展示站，成功后切换 current 版本入口并记录结果。
5. 失败写入日志及状态；服务重启会把遗留待处理或构建中记录标记为失败。

代码使用进程内队列和数据库状态检查。这不等于已验证多实例发布的并发安全。版本目录及切换链接应使用支持预期原子切换的文件系统布局。

## 预览访问

预览使用独立目录与入口，不直接替换正式版本。后台生成短期链接，预览服务验证后换成 HttpOnly Cookie，并区分 API 和预览令牌的 audience。

预览响应设置 noindex 和 no-store，预览构建不启用正式统计入口。实际域名、代理与 Cookie 行为需要在部署环境验收。

## 回滚与版本保留

回滚从目标成功版本快照重新构建新版本，记录回滚来源；不会把数据库里的未发布编辑覆盖为旧内容。构建目录默认保留 10 个，受 KEEP_RELEASES 配置控制，数据库快照与磁盘目录采用不同保留方式。

旧快照可能依赖已经删除的图片，也受当前模板和构建环境影响；保留快照不保证任意旧版本始终可复现。发布回滚与数据库备份恢复不是同一流程。
